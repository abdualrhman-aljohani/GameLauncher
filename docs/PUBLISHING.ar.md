# دليل النشر: GitHub والتوقيع الرقمي ومتجر مايكروسوفت

> مبني على توثيق مايكروسوفت وقت كتابته (سبتمبر 2026). الأسعار والشروط تتغير — راجع الروابط في آخر الملف قبل أي قرار مالي.

## 1) الخلاصة السريعة (لك، من السعودية)

| الخيار | يناسبك؟ | ملاحظة |
|--------|---------|--------|
| **Azure Artifact Signing** (اسمه القديم Trusted Signing، ~10$ شهرياً) | ❌ غير متاح لك | الأفراد فقط من أمريكا وكندا، والمؤسسات من دول محددة (أمريكا، كندا، الاتحاد الأوروبي، بريطانيا، أستراليا، نيوزيلندا، اليابان، كوريا الجنوبية، سنغافورة، سويسرا، النرويج، إسرائيل). السعودية ليست ضمنها. |
| **شهادة توقيع من جهة إصدار (CA)** — OV / Individual Validation | ✅ ممكن | تدفع سنوياً، والمفتاح يجب أن يكون على توكن/HSM (أو خدمة سحابية) بحكم قواعد CA/Browser Forum. تأكد أن الجهة تقبل التحقق بهويتك. |
| **متجر مايكروسوفت — حزمة MSIX** | ⚠️ مجاني لكن بقيود | مايكروسوفت توقّع الحزمة عنك. لكن تغليف MSIX يتعارض مع ميزات البرنامج (انظر القسم 4). |
| **بدون توقيع** + شفافية | ✅ حل مؤقت | SHA-256 في كل إصدار + بناء علني من GitHub Actions + إرسال الملف لتحليل Microsoft Defender. |

**حقيقة مهمة عن SmartScreen:** التوقيع يزيل عبارة *"Unknown publisher"*، لكن تحذير SmartScreen الأزرق يعتمد على **سمعة الملف** (عدد التنزيلات)، وشهادة **EV لم تعد تعطي سمعة فورية منذ مارس 2024** — فلا تدفع ثمن EV من أجل SmartScreen (وأصلاً EV للمؤسسات فقط عند بعض الجهات). شهادة OV/Individual كافية، والسمعة تتراكم مع الوقت.

## 2) توقيع الإصدار (لو اشتريت شهادة)

1. اشترِ شهادة **Code Signing** (OV أو Individual Validation) من جهة موثوقة (مثل DigiCert أو Sectigo أو SSL.com أو Certum). الخيارات السحابية (مثل Certum SimplySign) تغنيك عن توكن USB. أقصى صلاحية للشهادة الآن نحو سنة (تجدّدها من لوحة الجهة).
2. ثبّت **Windows SDK** (يحتوي `signtool.exe`).
3. الترتيب الصحيح:
   ```powershell
   # 1) ابنِ Release
   # 2) وقّع الـ exe
   .\tools\sign-release.ps1 -Thumbprint <بصمة الشهادة> -Files bin\Release\GameLauncher.exe
   # 3) ابنِ المثبّت (ISCC installer\GameLauncher.iss)
   # 4) وقّع المثبّت
   .\tools\sign-release.ps1 -Thumbprint <بصمة الشهادة> -Files dist\GameLauncher-Setup-1.8.0.exe
   ```
   (أو `-PfxPath` + `-PfxPassword` لو عندك ملف PFX.) السكربت يضيف **timestamp** (مهم: يبقي التوقيع صالحاً بعد انتهاء الشهادة) ثم يتحقق من التوقيع.
4. **لم أختبر السكربت على شهادة حقيقية** — جرّبه على نسخة تجريبية أولاً وابعث لي أي خطأ.

## 3) النشر على GitHub

1. أنشئ مستودعاً واحفظ المشروع فيه (يوجد `.gitignore` جاهز).
2. عدّل رقم الإصدار في: `Launcher/Launcher.rc` و`Launcher/Launcher.cpp` (`APP_VERSION`) و`installer/GameLauncher.iss` وشارة الإصدار في README، وأضف قسماً جديداً في `CHANGELOG.md`.
3. ارفع `tag`:
   ```bash
   git tag v1.8.0
   git push origin v1.8.0
   ```
   workflow الإصدار (`.github/workflows/release.yml`) يبني الـ exe والمثبّت وملف `SHA256SUMS.txt` ويرفقها بإصدار (Release) جديد. **لم يُختبر workflow عندي** — أول تشغيل قد يحتاج تعديلاً بسيطاً (مثلاً إصدار Visual Studio على الـ runner).
4. في ملاحظات الإصدار اذكر: طريقة التحقق من SHA-256، وأن الإصدار غير موقّع (إن كان كذلك).
5. أضف لقطات شاشة في `docs/images/` (يفضّل بخلفية محايدة بلا أعمال فنية لطرف ثالث) وفعّل السطر المعلّق في README.

**تقليل بلاغات الحماية الخاطئة (False Positive):** البرنامج يعدّل أولويات العمليات ويكتب في registry ويستخدم ETW، فقد يشتبه به بعض مضادات الفيروسات. أرسل الإصدار إلى تحليل مايكروسوفت: https://www.microsoft.com/wdsi/filesubmission (اختر Developer). ويُنصح بإرساله كذلك لشركات مضادات الفيروسات التي تظهر عندها المشكلة.

## 4) رفعه على متجر مايكروسوفت

حساب المطوّر: من `storedeveloper.microsoft.com`. توثيق مايكروسوفت يصفه بأنه **مجاني** وقت الكتابة (تأكد عند التسجيل)، ويتطلب التحقق من هويتك.

للمتجر مساران، ولكل منهما ثمن:

### المسار أ — مثبّت EXE/MSI (النسخة الكاملة بلا تغيير في الكود)
يحافظ على كل ميزات البرنامج (Boost وETW والتشغيل كمسؤول والتشغيل التلقائي). شروطه:
- المثبّت **وكل ملفات PE فيه** (الـ exe نفسه) موقّعة بشهادة من CA موثوقة — **الشهادة الذاتية (self-signed) غير مقبولة**. أي أنك تحتاج شهادة من القسم 2 أولاً.
- تثبيت **صامت** بلا واجهة (المثبّت يدعم `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART` — تدخّل UAC مسموح).
- مثبّت **كامل غير معتمد على التنزيل** أثناء التثبيت (لدينا كذلك).
- رابط **HTTPS ثابت ومرقّم بالإصدار** لا يتغير محتواه بعد الرفع (رابط ملف من GitHub Releases مناسب). لكل إصدار جديد تقدّم رابطاً جديداً.
- تحديثات الإصدارات مسؤوليتك (المتجر لا يديرها لهذا المسار).

### المسار ب — حزمة MSIX (مجاني، ومايكروسوفت توقّع عنك)
لا تحتاج شهادة. لكن هذا تقدير مني وليس اختباراً: تطبيقات MSIX لا ترفع صلاحياتها كتطبيق عادي (ذلك يتطلب قدرة مقيّدة `allowElevation` يُستبعد اعتمادها في المتجر حسب مصادر المطورين)، وعليه:
- **Boost** (يكتب في `HKLM`) و**Black Box FPS** (ETW يحتاج مسؤول) و**التشغيل كمسؤول** قد لا تعمل داخل الحزمة.
- التشغيل التلقائي (مهمة مجدولة + مفتاح Run) قد يحتاج أسلوباً آخر (StartupTask).
فتكون نسخة المتجر **مخففة** وتحتاج تعديلات كود.

### خطوات الرفع (كلا المسارين)
1. Partner Center ← **New product** ← احجز اسم التطبيق (يجب أن يكون فريداً).
2. **Pricing and availability:** مجاني، واختر الدول.
3. **Properties:** الفئة (Utilities أو Games)، وتصنيف العمر (استبيان IARC).
4. **Store listing:** وصف بالإنجليزية (والعربية اختياري)، لقطات شاشة، أيقونة (`docs/images/icon.png`)، وصفحة **سياسة خصوصية** إن كان التطبيق يصل لبيانات (أنصح بصفحة بسيطة تقول: لا جمع بيانات ولا حسابات).
5. **Packages:** رابط المثبّت (المسار أ) أو ملف MSIX (المسار ب).
6. أرسل للمراجعة (Certification) — تستغرق عادة أياماً، وقد يطلبون توضيح ما يفعله البرنامج بإعدادات النظام.

### توصيتي
ابدأ بـ **GitHub + المثبّت** (مع شفافية SHA-256). عندما تشتري شهادة وقّع الإصدارات، ثم فكّر في **المسار أ** للمتجر. **المسار ب** فقط لو تريد نسخة مخففة بدون ميزات النظام.

## 5) قائمة تحقق قبل كل إصدار
- [ ] رقم الإصدار موحّد (rc + APP_VERSION + iss + README + CHANGELOG)
- [ ] بناء Release ناجح + `tests/` تعمل
- [ ] تجربة: تثبيت جديد، ترقية، إزالة (وتأكد من استرجاع Boost)
- [ ] توقيع الـ exe ثم المثبّت (إن وُجدت شهادة)
- [ ] رفع tag والتحقق من الملفات وملف SHA-256 في Release
